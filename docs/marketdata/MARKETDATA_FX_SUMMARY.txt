═══════════════════════════════════════════════════════════════════════
PROBLEMS IDENTIFIED
═══════════════════════════════════════════════════════════════════════

1. ❌ MISSING SEPARATION OF CONCERNS
   - Service layer tightly coupled to database
   - Cannot test API logic independently
   - Violates Single Responsibility Principle

2. ❌ INCONSISTENT WITH ESTABLISHED PATTERNS

   Service        Has CRUD    Has Parser    Service Responsibility
   ────────────────────────────────────────────────────────────────
   binancecom       ✅          ✅          API only
   ibkr             ✅          ✅          API only
   crypto_wallet    ✅          No*         Orchestration
   marketdata       ⚠️          ❌          API + Transform + DB ← WRONG
   fx               ⚠️          ❌          API + Transform + DB ← WRONG

   * crypto_wallet: providers handle normalization (different pattern)

3. ❌ CRUD LAYER IS WEAK
   - Just thin ORM wrappers
   - No business logic
   - No batch operations
   - No error handling
   - No success/failure counting
   - No logging

4. ❌ NO PARSER DESPITE COMPLEX TRANSFORMATION
   Current code in service layer:
   
   for symbol, symbol_data in data['data'].items():
       price = symbol_data['quote']['USD']['price']  ← Should be in parser
       upsert_market_data(session, ...)

5. ❌ CACHING IMPLEMENTATION ISSUES
   @cache(ttl=CACHE_TTL, maxsize=CACHE_MAXSIZE)
   def fetch_and_record_crypto_prices(session):
       # Problem: Function does TWO things (fetch AND record)
       # Problem: Cache key includes DB session object
       # Problem: Cache at wrong level (should cache API, not DB ops)

6. ❌ FALLBACK LOGIC IN WRONG LAYER
   Service layer handles:
   - Try CoinMarketCap → Try yfinance → Try database → Record
   Should be separated into different concerns
